## What this PR does

Transforms Jarvis from a reactive CLI into a self-driving agentic system. The core shift: instead of prompting agents manually, this builds loops that prompt agents automatically.

## Autonomous Orchestration
- **`orchestrator_loop.py`** — single-iteration loop: harvest completions → suggest follow-ups via local LLM → pick next queued task → write to LAUNCH_QUEUE.json
- **`harness/prompt_generator.py`** — local LLM (qwen3:30b-a3b) generates full session prompts from task specs; template fallback when Ollama is unreachable
- **`harness/session_tracker.py`** — atomic ACTIVE_SESSIONS.json: claim, complete, stall detection
- **`harness/cowork_launcher.py`** — reads LAUNCH_QUEUE.json, fires prompts to PENDING_SESSIONS/, harvests completions
- **`harness/loop_monitor.py`** — live dashboard text: queue depth, active sessions, stall alerts
- **`scripts/com.jarvis.loop.plist`** — Mac launchd job running every 5 minutes (already loaded)

## Unified Dashboard
- **`jarvis_dashboard.py`** — FastAPI server at localhost:7842, 5 tabs: Overview, Work Queue (kanban), Training (live charts), Ops (8765 iframe), Activity (log + self-eval)
- Replaces 3 separate dashboards (7842 kanban, training/dashboard.html, static reports)
- Auto-refreshes every 15s via fetch(), no full reload

## New Commands
- `/diagnose` — health check across 8 subsystems (Ollama, memory, auth, budget, self-eval, router, tests)
- `/status` — live orchestration state: queue depth, active sessions, stalls
- `/summarize <text or file>` — LLM summarization using ornith-9b → qwen3 → mistral fallback
- `/cancel` — gracefully stops a running task at the next step boundary
- `/watch <path>` — monitors files, fires macOS notification on change
